PaperEngineArena

Reduction Arena

These are real levels built by the NP-hardness reduction (tools/gen_on_instance.py): each one turns a small logic formula into a NetHack boulder maze. The rule the proof claims: you can reach the goal G exactly when the formula can be made true. On a solvable level, find the route. On an impossible one, the proof says there is no route, so if you ever reach G on an UNSAT level, you have found a bug in the proof. That is the useful kind of intuition here.

How a level is laid out

  • You start at the left end of the long main line (middle of the map). Walk right along it.
  • At each variable the line splits in two. Top branch = x false, bottom branch = x true. Pick one; they rejoin.
  • Each branch has boulders you are forced to shove sideways. Each shove permanently blocks a clause path: the top branch blocks paths for literal x, the bottom one for ¬x.
  • After the last variable you climb into the clause checks (positive clauses above the line, negative below). Each clause has up to 3 parallel paths, one per literal. You need one still open path through every clause to reach G.

Rules (exactly the proof's)

  • Push a boulder by walking into it orthogonally, if the square behind is free.
  • No diagonal pushes; no diagonal squeeze between two boulders/walls.
  • Walking into a hole ^ = you fall off the level = lose (undo is allowed here).
  • Pushing a boulder into a hole plugs it, making floor. Crossovers use this: one-time passages.
  • Hunger is ignored here. That only gives you more power, so it is fine for bug hunting.

How to break it

  • Look for a route on a UNSAT level: skip a forced shove, sneak a boulder into the wrong corridor, cross a path twice, plug a hole from the wrong side.
  • The 5 open levels are the ones the computer has not finished checking (over 26 million states each). A route there would be a real counterexample.
  • Not finding one proves nothing by itself, but it tells us where to look.
